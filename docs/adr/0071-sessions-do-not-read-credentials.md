# Sessions Do Not Read Credentials

ADR 0011 has secret-touching actions denied or strongly confirmed, and ADR 0026 keeps them denied inside an Effect Envelope. Only the write side ever implemented it. `classifyPath` in `src/tools/actionable.ts` marked a patch target `sensitive` and refused it; the read side had no such classification to return, so `.env` was an ordinary low-risk read that the Permission Policy allowed without a prompt.

Session `sess_msb4s8jp` showed the shape of the leak. Nobody named `.env` as a read target — a whole-workspace `search_text` walked past it and printed `.env:2: DEEPSEEK_MODEL=deepseek-v4-flash` into the conversation. The neighbouring lines were a live `DEEPSEEK_API_KEY` and `BRAVE_SEARCH_API_KEY`, one matching query away from the same trip, and a Tool Observation is persisted to the Trace verbatim. The file is git-ignored precisely because its content must not travel; the read tools were the one path that carried it anyway.

So the read boundary now matches the write boundary here too, the way it already does for internal state (ADR 0069). Credential files are named once in `src/secretPaths/`, and both directions consult that list: `read_file`, `list_files`, `search_text`, and `workspace_summary` classify a directly named credential path as `sensitive` and the Permission Policy denies it, while workspace traversal skips those files so a search cannot print a line out of one in passing.

The read list is deliberately narrower than the write side's older name heuristic (`secret`, `token`, `credential`, `key` anywhere in the path), which stays in force for patches. The asymmetry is about what a false positive costs: refusing to patch `src/auth/token.ts` costs a pause the user can approve, while refusing to read it would make ordinary source unreadable for the rest of the Session with no recourse. The shared list is what closes the names the heuristic never matched — `id_rsa`, `deploy.pem`, `.npmrc` — so the write side gets stricter in the same change. `.env.example` and its siblings stay ordinary in both directions on the read side: they carry variable names, never values, and README points at them.

The escape hatch is the Session Read Scope, as it is for internal state: an `--allow-read` entry naming the credential file grants exactly that file. A scope of `.` or `src` does not, so widening read scope for ordinary work cannot widen it onto secrets.
