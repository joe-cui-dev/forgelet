# Style Presets Ship Built-In with Additive Workspace Overrides

Forgelet previously required each workspace to define its own Style Preset vocabulary, with a git-ignored local file replacing the committed one wholesale. That made a general prose vocabulary — `plain`, `vivid`, `tight`, and the rest — a per-workspace obligation, and forced anyone adding one private preset to duplicate every shared one. Forgelet now ships that vocabulary as a built-in default set, and `.forgelet/style-presets.local.json` merges over it by key: a preset with a new name extends the vocabulary, one reusing a built-in name replaces that preset whole rather than amending its fields. The committed `.forgelet/style-presets.json` layer is dropped instead of kept as a middle tier, and a malformed local file fails the Session rather than falling back to the defaults — a silent fallback would let a Session run in the wrong style with nothing to show for it.
