# Browser Invocations Carry a Per-Invocation Route Override

Browser Workbench keeps a sticky selector for Default route, Flash, and Pro. Default omits a model field; a selected model is snapshotted on each root, follow-up, or Retry gesture and flows both to the live model client and to the Session Route recorded in its Trace. This is an explicit invocation override, like the CLI `--model` precedent, not user-configurable Routing Policy: ADR 0005 still keeps that policy out of configuration, and ADR 0066 still keeps Model Profiles as provider facts rather than configuration. The Browser protocol validates the override against non-retired Profiles before Session creation, preserving a clean launch rejection rather than a zero-turn Session; the existing budget remains its same money upper bound. We rejected making routing configurable, always sending the current default, dynamically deriving selector choices through a new host command, pinning the choice in a Page Conversation projection, scaling the budget by model price, and persisting the chosen model on completed turns. Those options either change shared CLI policy, duplicate profile facts, expand the disposable projection schema, weaken the Budget's upper-bound meaning, or create state that an invocation Trace already records truthfully.
