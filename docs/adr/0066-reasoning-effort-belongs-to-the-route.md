# Reasoning Effort Belongs to the Route, Validated by a Model Profile

ADR 0005 routes by Workflow and stage, and a Route has so far been a single model id. Reasoning effort now changes a Session's cost, latency, output quality, and — through ADR 0065's uncompactable Provider Carryover — its survival, which makes it as load-bearing as the model id itself. We decided a **Route** is the pair: which model answers and how much effort it spends. Effort is expressed as one enum, `none | low | high | max`, folding the on/off switch into the depth scale rather than carrying a separate boolean; this is DeepSeek's own Responses shape, so the door ADR 0068 leaves closed stays cheap to open. Defaults are `high` for coding, where the published agent benchmarks live, `high` for learning and writing — writing's current behaviour, which has been shipping satisfactory prose with thinking on since V4 — and `none` for the Rolling Summary call, which writes a summary, needs no reasoning, sends no tools, and charges its reasoning tokens to the Session under ADR 0019.

Effort travels with the Route into `routing_selected` and into the Pause Snapshot. Under ADR 0059 it is added as an optional payload field, never a repurposed one. The reason is evidential rather than tidy: two Sessions on the same model and the same task can now diverge sharply, and a Trace that cannot name the effort cannot explain the divergence. We rejected letting the kernel pick effort dynamically from remaining budget — ADR 0005 exists to keep routing explainable rather than a hidden automatic classification, and per-turn effort drift would make a Session's own behaviour unexplainable from its Trace.

A Route can now express combinations a provider will not honour: `deepseek-v4-pro` currently accepts only `high` and `max` and silently remaps `low`, and DeepSeek silently ignores unsupported parameters generally, so probing at runtime cannot detect the mismatch — the Trace would simply record an effort that never ran. We therefore introduce a **Model Profile** as the single source of the facts Forgelet holds about a routable model: protocols, accepted efforts, context and output ceilings, prices, and retirement status. Runnability moves off the `startsWith("deepseek-")` prefix test, which still answers yes for `deepseek-chat` and `deepseek-reasoner` five weeks after their 2026-07-24 retirement; retired ids get a migration message, unknown ids fail at route selection rather than mid-Session, and the pricing table folds into the Profile instead of being a second half-catalog. Profiles are provider facts, not user policy, so they are not exposed to configuration — ADR 0005 already keeps even the routing policy out of user config, and facts belong there less than policy does.

**2026-08-13**: The motivating example above is no longer accurate. As of DeepSeek-V4-Pro-0813 — an in-place update under the unchanged `deepseek-v4-pro` id — the model accepts `low` and honours it, and its published effort mapping is identical to `deepseek-v4-flash`'s. Its Profile now lists the same efforts. The decision stands unchanged, and this episode exercised it: absorbing the change meant editing one Profile field rather than hunting behavioural assumptions through the codebase. One consequence is worth recording — no live Profile restricts efforts any more, so the runnability check's effort branch has no real example left and the test that covered it was removed rather than rebuilt on a synthetic Profile.
