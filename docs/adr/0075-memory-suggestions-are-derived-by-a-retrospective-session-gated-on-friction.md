# Memory Suggestions Are Derived By A Retrospective Session Gated On Friction

ADR 0064 diagnosed Durable Memory's failure as supply rather than selection and left the supply side unfixed. Sixty-one Sessions later nothing has changed: across 357 Sessions the dogfood workspace still holds zero Memory Suggestions and zero Memory Decisions, and `.forgelet/memory-suggestions.jsonl` has never existed. `.forgelet/memory.md` now has content, but both entries in it were typed by hand. The single generator, `formatActionableAuditMemory`, gates on actionable-audit evidence — 8 of 87 Coding Sessions ever recorded `changedFiles` — and the one sentence it can emit is already stated in `AGENTS.md`.

The gate therefore moves from success to friction. A discovered convention is found where a Session's expectation did not match the workspace, so the deterministic gate becomes the **Friction Signal**: a Tool Observation that failed, or a Permission Policy decision that denied the call or required confirmation. Across the same 357 Sessions that gate admits 30 — 27 Coding, 3 Learning, and no Writing Session at all — against the audit gate's 8, and it needs no per-workflow filter to get there. The two hand-written entries confirm the shape: *read Session history by globbing that directory, not by descending into it*, and *a Trace does not contain the full conversation*. Both are the residue of hitting a wall, and neither is reachable from `changedFiles` and a green command.

Derivation becomes a Session. `forge memory suggest <sessionId>` runs a **Retrospective Session**: no tools, a single node, the source Trace supplied as a Context Attachment — ADR 0069 denies reading `.forgelet`, and attaching is the audited path — with the Anchor Files and the current Durable Memory alongside it so candidates that merely restate declared guidance are dropped. That semantic comparison, named in ADR 0064 as the real reason the proposal side needs a model, is most of the model's job. A bare `modelClient.createTurn` in the manner of a conversation fold would have been smaller, but it would leave Forgelet with one model judgement that spends money and ultimately shapes `AGENTS.md` while carrying no Trace, no Route, and no budget to account it against; iterating on that prompt would also mean building an observation surface that `--debug` and `forge explain` already provide. Project Memory Review stays deterministic and model-free — the boundary is proposal versus decision, not memory versus everything else.

## Consequences

- Derivation stays single-Session, so schema v1, the Provenance Snapshot, the Memory Decision Log, and Compatibility Import are untouched. Batch is a loop over admitted Sessions, not a second derivation shape.
- A Retrospective Session yields 0..N suggestions, and a Session carrying no Friction Signal yields nothing instead of throwing.
- The Rendered Memory Block becomes a single bullet with trailing provenance rather than an `## id` block, matching the file a human already maintains and cutting the noise that whole-file injection (ADR 0032, ADR 0064) puts in front of every later Session. It is changed now because the Memory Decision Log holds no acceptance, so byte identity costs nothing to move today and gets expensive the moment it does.
- `smoke:memory-review` seeds its versioned suggestion by writing the record directly instead of calling `forge memory suggest`, keeping its no-API-key proof pointed at the four review commands it actually covers. The seed for a review test should not depend on a model outside the thing under test.
- Retrospective stays manually triggered. Proposing automatically at Session end would have to answer the roadmap's ban on undeclared Session starts, and it should not be answered before the batch shows the output is worth queueing at all — a Decision Queue filled with noise fails more quietly than one that is empty.
- If the batch over the 30 admitted Sessions yields fewer than three suggestions worth accepting, the supply hypothesis is wrong. Record that here and stop; do not keep tuning the prompt.
