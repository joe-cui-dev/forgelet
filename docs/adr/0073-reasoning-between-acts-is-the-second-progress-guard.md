# Reasoning Between Acts Is the Second Progress Guard

ADR 0070 gave the ReAct loop a progress guard beside its consumption guards, and it holds — for the loop it was built from. It does not hold for the shape three Sessions found next. `sess_msbgz2m0`, `sess_msbi6hsq`, and `sess_msbid1es` ran the same task minutes apart, spent eighteen, thirteen, and thirteen turns on it, and every one of them had to be killed by hand. In all three the gate scored **every turn as advancing**: `noProgressTurns` never left zero. That was not a bug in the counting. Each turn genuinely learned something the Session did not already hold — one more search that matched one more line, one more file range it had not opened. The Sessions were converging on nothing while satisfying the definition of progress, and the guard is blind to that by construction.

Two things let it through, and both are fixed here.

The first is that a re-worded miss read as new evidence. A `search_text` that finds nothing returns an empty observation whose summary carries the query — `Found 0 matches for "token"` — and the digest hashed the summary, so searching a different word for the same nothing minted a new fact and reset the streak. **An observation that came back empty now folds onto one digest per tool.** The query that failed to find anything is not itself a fact, and a Session that varies its wording through a run of misses is doing the thing the streak exists to catch. This is a correction to ADR 0070's own rule, not a new one: it said reads count only when the observation is new, and an empty result is not new the second time however it was asked for.

The second is that the streak is the wrong instrument for this loop, because the loop advances. So the gate gets a second road to the same wrap-up: **reasoning spent since the Session last acted on the world**. Only an effect clears it — a patch applied, a command run, a plan rewritten — because a Session can keep learning true, useless facts indefinitely, and the recorded divergences did exactly that. Crossing `NO_PROGRESS_REASONING_TOKEN_LIMIT` reserves the wrap-up turn of ADR 0029 through the same `forcedStopReason` seam, and the ceiling is read even on a turn that advanced, since otherwise it is unreachable in precisely the case it exists for. The Trace records which road fired, so `session_no_progress` still answers why in one place.

This is not the reversal of ADR 0070's rejection that it looks like. That ADR rejected *acting on* reasoning volume — moving a Session's effort mid-run, which ADR 0066 forbids because it makes behaviour unexplainable from the Trace. Reading reasoning volume as a trip-wire for a wrap-up the Session was always going to be allowed changes no Route and leaves the Session's answer its own. What 0070 got wrong was narrower: it treated yield as the only honest measure, and yield turned out to be satisfiable by a Session that is going nowhere.

The threshold is 32,000 tokens, and it is the weakest part of this decision. It was set by replaying every recorded Coding Session against the gate: the three that had to be killed crossed it at turns 11, 12, and 12, and the two that converged peaked at 13.2k and 14.8k. But `sess_msa9tww4` — the Session that motivated ADR 0070 in the first place — investigated for eleven turns, peaked at 30.2k, then acted and finished, and the ceiling deliberately sits just above it. The usable band between the healthiest survivor and the cheapest divergence is roughly 30k to 33k, which is a thin place to put a constant. We accept it because the intervention is a wrap-up and not a cut: a Session clipped early answers from what it already holds rather than losing its work, and the number should be re-derived as Sessions accumulate. It stays a module constant rather than a Session Budget for that reason — it is a heuristic under calibration, and promoting it to `budgets` would imply a stability it has not earned and a CLI surface we would then owe compatibility to.

One consequence is worth naming: the reasoning counter is cleared by acts, not by turns, so a legitimately long read-only investigation — a Session asked to explain rather than change anything — will reach the ceiling on a schedule set by its Route's effort. That is the intended reading. A Session that has thought thirty-two thousand tokens' worth without touching the workspace has enough to answer with.
