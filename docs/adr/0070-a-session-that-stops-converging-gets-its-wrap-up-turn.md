# A Session That Stops Converging Gets Its Wrap-Up Turn

Every guard on the ReAct loop measures consumption: turns taken, cost accrued, wall clock elapsed. None measures whether the loop is getting anywhere. Session `sess_msa9tww4` finished inside all three — nineteen of thirty-two turns, twenty-three percent of the cost ceiling, seven minutes of thirty — while spending turns whose reasoning grew from thirty-eight tokens to eight thousand and whose visible content restated the previous turn's conclusion almost verbatim. On a cheap model with a wide context, the consumption budgets are simply too loose to notice; ADR 0067 widened the conversation budget an order of magnitude and made that looser still. Worse, the loop has an unbounded path with no consumption at all worth noticing: a model that returns neither tool calls nor usable content is sent straight back around, and only the turn ceiling ends it.

We decided the loop needs a **progress** guard beside its consumption guards. A turn advances the Session when it acts on the world or learns something the Session did not already hold. Effects always count — a patch applied, a command run, a plan rewritten — because repeating one is a deliberate act rather than a stall, and re-running a suite after an edit must not be read as spinning. Reads and searches count only when their observation is new: re-reading a range the conversation already carries teaches nothing, whatever the turn spent deciding to read it again. Three consecutive turns that meet neither test reserve the wrap-up turn of ADR 0029, through the `forcedStopReason` seam that already exists for a user stop, and the Session stops with reason `no_progress` and the model's closing answer attached. Three, because one barren turn is ordinary and two can be the recovery from it.

The intervention is a wrap-up rather than a cut, and the closing turn is told why it was reserved, so a Session that stopped converging says so in its own answer instead of presenting a partial result as a finding. The Trace records each barren turn as `session_no_progress` with the reasoning tokens spent across the streak — the cost the gate exists to stop, in the unit that makes it visible, since reasoning is otherwise only legible by differencing per-turn telemetry.

We rejected acting on reasoning volume directly. It is the symptom that makes the waste visible, but a Session cannot be told to think less without changing its Route, and ADR 0066 already rejected letting the kernel move effort mid-Session: per-turn effort drift would make a Session's behaviour unexplainable from its own Trace. Yield is the honest thing to measure, and it is measured in the vocabulary the Fact Ledger already uses for what a Session has learned. We also rejected persisting the streak into the Working State. A Session that pauses for approval and resumes starts its count fresh, which fails toward letting work continue rather than toward cutting it short, and keeps the Pause Snapshot schema unversioned by this change.

One consequence is deliberate and slightly untidy: the reserved turn is announced by the existing `budget_wrapup_triggered` event carrying `reason: "no_progress"`, so a Trace still has one place that answers "was a wrap-up reserved, and why", even though this cause is not a budget.
