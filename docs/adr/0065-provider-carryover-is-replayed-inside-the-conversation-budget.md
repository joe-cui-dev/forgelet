# Provider Carryover Is Replayed Inside the Conversation Budget

DeepSeek V4 enables thinking by default at `high` effort, and its documentation requires that a turn's `reasoning_content` be replayed verbatim on every subsequent request that carries `tools`, returning HTTP 400 otherwise. A model turn therefore now produces a third kind of output beside the answer and the tool calls: state Forgelet neither authors, reads, nor may rewrite. This collides with the premise of ADR 0013 and ADR 0019, where Forgelet owns the model-facing conversation and may compact it freely. We considered running tool-carrying Sessions with thinking disabled to keep that premise intact, and rejected it: the agent gains that motivate V4 Flash at all — the Terminal Bench and NL2Repo results DeepSeek publishes at `max` effort — are exactly what thinking buys, so refusing the state would mean refusing the upgrade.

We decided to name it **Provider Carryover** and model it as a first-class part of the conversation: attached to the assistant turn that produced it, replayed opaquely, never rendered as content, never compacted on its own, and discarded with its turn when that turn folds. It counts against `activeContext.maxConversationBytes`, because those bytes are sent and a budget that excludes them stops describing what leaves the machine; a separate carryover byte count appears in Turn Status so the two halves of the budget stay distinguishable. This makes Carryover Forgelet's first uncompactable budget consumer — Observation Digests and the Rolling Summary have no purchase on it — which is why ADR 0067 raises the budget rather than leaving the `max` effort path to die against ADR 0019's "the Session stops" clause. Carryover never crosses a Session boundary: ADR 0014 has Continuations inherit compact evidence, and a payload bound to one provider request chain is neither evidence nor valid elsewhere.

Carryover reaches disk in a Pause Snapshot, which persists raw reasoning without the ADR 0018 opt-in. That is not a new decision: ADR 0033 already accepted persisting model-facing content by bounding its lifetime rather than its content, and Carryover inherits that acceptance — the snapshot is deleted on resume or terminal outcome. The Trace records byte counts only; the Debug Transcript records it whole, as it already does for every model exchange. The kernel keeps a configuration path to set effort to `none`, so the whole class of requirement can be switched off in one place if a provider tightens or changes it. One caveat is recorded deliberately: dogfood Sessions through 2026-07-19 ran up to nine model turns and thirty-six tool events against V4 Flash and V4 Pro with no replay and no 4xx, so the preview build did not enforce the documented rule. We build to the documented contract anyway, because depending on undocumented leniency from a model that was just re-post-trained is the more fragile bet.
